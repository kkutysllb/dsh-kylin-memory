# 0102 抽取合同与失败语义

> 状态：与 `src/extractor/` 当前实现同步。

## 合同结构

每个完成轮次**恰好一次**辅助 LLM 调用，输出一个扁平对象（`src/extractor/contract.ts`）：

```ts
{ summary: string, outcome: "completed"|"partial"|"failed"|"informational"|"unknown",
  triples: [{ subject, predicate, object }] }
```

设计要点：

- 摘要与 SPO 来自**同一次调用**——拆两次调用成本翻倍且可能互相矛盾；
- SPO 只从摘要拆分，是导航索引，不是第二事实体；
- 扁平结构 + 单层枚举：在无约束采样的 provider 上遵循率更高；运行时仍用 TypeBox `Value.Check` 全量校验（fail-closed，最多报 3 条错误路径）；
- 模型必须调用一次 `submit_result` 工具，只认工具参数，文本前言忽略（warn 不入库）；
- **不做** JSON repair、默认字段补全、语义方向门禁、自动造边、失败循环重试。坏数据不能伪装成成功数据。

## 提示词

- `<Current Turn>`（用户问题 + 最终可见回答）是唯一事实来源；
- `<Previous Turn Summaries>` 只用于消解"继续这个/按刚才的方案"等指代，显式声明不是本轮事实；
- 无明确关系时 `triples: []` 合法；不限制节点/边数量与文字长度；
- 带 3 个 few-shot 示例与"调用前自检"清单。

## 写入原子性与稳定身份

（`src/store/store.ts`）

- turn memory ID = SHA-256(sessionId + 排序后的 source message IDs)：重放同一轮不产生重复记忆；
- term ID = SHA-256(规范化词项)：同一实体跨轮复用同一导航节点；
- triple ID = SHA-256(memoryId + subjectId + predicate + objectId)；
- `replaceNavigationTriples()` 单事务替换某轮全部 SPO，失败整体回滚；
- 只做空白规范化，不重写模型的 subject/predicate/object 语义。

## 失败语义与队列

（`src/index.ts` 的 `extractChain` / `scheduleExtract` / `drainTurn`）

- 每 session 一条串行 Promise 链：不会乱序写入，不会有第二个 worker 消费同一轮；
- 只调度 live `turn/end`，不扫描启动前的历史；
- 三态分拣：
  1. 关机/中止 → 留 pending（生命周期背压，不隔离）；
  2. 路由不可用（`DshExtractionUnavailableError`，如请求的 effort 不被 provider 广告）→ 记失败、停住不循环重试，可恢复；
  3. 其他错误（含合同校验失败）→ 隔离；
- 隔离 = `extraction_state='quarantined'`，毒消息保持持久且显式未学习；恢复路径：启用 `assistantTools: all` 后调用 `km_retry_extraction`；
- 隐私：错误日志不含模型输出原文，错误字符串截断 2000 字符。
