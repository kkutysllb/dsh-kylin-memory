# 0103 召回管线

> 状态：与 `src/recaller/recall.ts` / `src/graph/` 当前实现同步。

自动召回挂在 `agent/pre-step`（仅 `step===1` 且有真实用户 query），不依赖任何工具调用。召回快照作为 `source.kind="plugin:kylin-memory"` 的 user 消息插在当前用户消息**之前**，并显式标注"不可信历史参考，当前用户指令优先"。

## 双路召回

1. **摘要路线**：query embedding 对 `km_turn_vectors` 做余弦 Top-K（门槛默认 0.70，按 text-embedding-v4 语料 p90 校准）；词法路线（m18）为 **trigram FTS5**——CJK 子串可用（"端口 9090" 命中 "9090 端口"），<3 字符或 FTS 不可用时回退**完整短语** LIKE 兜底。三路线均可按 `workspace_id` 过滤（`recallScope`）。
2. **图路线**：查询中的具体词项与导航词项做字面双向子串匹配（"最具体短语优先"去 hub），字面无命中才用摘要命中轮次的 SPO 端点当种子 → 种子所在 LPA 社区给出候选集 → 在 SPO 导航图上跑查询时 Personalized PageRank → 端点最大分把词项分数映射回 turn memory（防多三元组轮次靠边数作弊）。

两路用 **RRF（1/(rank+1)）** 融合：cosine 与 PageRank 量纲不可比，刻意不直接相加；双路同时命中的记忆自然上升，摘要直接命中平分优先。图路线分数可按 `freshnessHalfLifeDays`（默认 0=关）做 exp 半衰期衰减。

**事实失效过滤**：结果集中若某记忆的 (subject, predicate) 已被更新的记忆显式失效（m17 `superseded_by`），旧记忆被剔除；失效者不在召回结果中时旧记忆保留（可能仍是该查询最好的上下文）。

## 命中之后

- 只回传**最能解释本次路由**的 SPO（`getNavigationTriplesForMemories`）；
- 摘要作为检索说明；
- 原始用户问题 + 最终可见回答按 `source_order` 恢复，装进 `<episodic_context>`；
- 当前最近窗口内已完整可见的 source message 不重复注入（`filterDshRecallMemories`）；
- 无关问题不因 Top-K "永远有最近邻" 而污染上下文：低于 `semanticScoreThreshold` 的直接命中被丢弃。

## 本地图算法（零 LLM、零第三方库）

- **LPA**（`src/graph/community.ts`）：每轮抽取成功后在 SPO 导航图上增量运行；排序遍历 + 平票取字典序，保证确定性；社区只用来缩小 PPR 候选，**绝不整包注入提示词**。
- **PPR**（`src/graph/pagerank.ts`）：teleport 回种子而非全体；图结构按 SQLite 连接缓存在 WeakMap，SPO 事务成功后显式 `invalidateGraphCache()`（不用全进程单例 + TTL，避免多 profile 串图）；重复出现的真实 SPO 形成重复邻接贡献（多轮证据强度），不发明"模型置信度"。

## 旧库回退

`recallPrecise`：仅当库中没有任何 turn memories（如旧版本数据）时，走节点级语义 + FTS5/LIKE，图扩展深度 0（不允许无关 hub 进提示词）。
