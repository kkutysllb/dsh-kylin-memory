# 0101 双通道适配与契约层

> 状态：与 `package.json` / `cordis.patch.yml` / `src/index.ts` 当前实现同步。

## 双通道机制

QiLin 是 deepseek-harness 的本地 fork（`@deepseek-ai/*` → `@qilin/*`），插件 API 同名同签名（`ctx.sessions/tools/llm/agents/systemPrompt`、`agent/pre-step`、`session/event`、`SurfaceOp` 全部一致）。因此本插件**代码层零分支**：

- `package.json` 同时声明 `dsh.bundle.patch` 与 `qilin.bundle.patch`，内容相同，指向同一份 `cordis.patch.yml`；
- DSH 宿主读 `dsh.*` 键，QiLin 插件管理器只认原生键 `qilin.bundle.patch`；
- 两通道加载同一个 `lib/index.js`，行为完全一致。

## 契约层（inject）

```ts
export const inject = ["tools", "llm", "systemPrompt", "agentLoop", "agents", "sessions", "credentials", "tokenMeter"];
```

零 `@deepseek-ai/*` 运行时导入（`scripts/smoke-plugin.mjs` 强制检查）：宿主能力全部经 inject 服务名在运行时到达，`DshContext` 等类型面在 `src/index.ts` 内以防御性接口手写声明。`scripts/build.mjs` 将 `@deepseek-ai/*` 与 `cordis` 保持 external。

插件触达的宿主契约面：

| 契约 | 用途 |
|---|---|
| `agent/pre-step`（waterfall） | 前置压缩（`prepend: true`）+ step===1 自动召回，返回 `{ kind: "enter", messages }` |
| `session/event` | `turn/end` 时依次：轮次落库 → 排程抽取 → 周期维护 → 轨迹投影 |
| `ctx.llm.stream` | 抽取旁路调用（强制单次 `submit_result` tool-call） |
| `ctx.credentials.resolve` | embedding API key 经宿主凭证解析 |
| `ctx.tokenMeter.measure` | 表面替换的影子 token 记账 |
| `ctx.tools` | 注册 km_* 工具 |
| `ctx.effect` | 关机清理（中止抽取、等待队列排空、关库） |
| `ctx.inject(["webServer","connection"], cb)` | 动态子世界注入：Web 面板 RPC 为可选面（见 docs/01-tech/0105），web 栈存在才注册通道，极简 profile 不受影响 |

注意：`webServer`/`connection` 刻意**不进静态 inject**——实测放进 inject 会让插件在无 web 栈的极简 profile 永久 pending（QiLin "waiting for services"），面板必须是可选面。

## 为什么 patch 是纯静态 YAML

上游 graph-memory 在 `cordis.patch.yml` 里用 `!!js` 表达式读环境变量和 `dshHomePath()`。这依赖宿主的 patch 表达式求值器，QiLin 不保证提供。因此本插件：

1. `cordis.patch.yml` 只写静态值（smoke 检查禁止出现宿主脚本表达式）；
2. 环境变量回退与路径解析全部收进 `src/index.ts` 的 `withEnvironmentDefaults()`，双宿主一致且可单测；
3. 显式 bundle 配置永远优先于环境变量。

## 路径与环境变量解析（适配器内）

数据库位置：`KYLIN_MEMORY_DATA_DIR` → `$DSH_HOME` → `$QILIN_HOME` → `~/.dsh`，默认落 `<home>/kylin-memory/kylin-memory.db`。

| 环境变量 | 作用 |
|---|---|
| `KYLIN_MEMORY_DATA_DIR` | 数据库文件目录覆盖 |
| `KYLIN_MEMORY_DB_BUSY_TIMEOUT_MS` | SQLite 写锁等待（默认 5000） |
| `KYLIN_MEMORY_LLM_PROVIDER` / `_MODEL` | 独立抽取路由（优先于前台 Agent 路由） |
| `KYLIN_MEMORY_LLM_REASONING_EFFORT` | 抽取推理档位（缺省时协商：优先 off） |
| `KYLIN_MEMORY_LLM_MAX_TOKENS` | 抽取响应上限 |
| `KYLIN_MEMORY_EMBEDDING_API_KEY` / `_BASE_URL` / `_MODEL` / `_DIMENSIONS` | 语义向量召回（缺省 FTS5） |
| `KYLIN_MEMORY_SEMANTIC_SCORE_THRESHOLD` | 余弦相似度门槛覆盖 |

## 安装（三方插件）

```bash
# DSH 通道
dsh plugin --profile web add dsh-kylin-memory          # npm 发布后
dsh plugin --profile web add github:kkutysllb/dsh-kylin-memory#v0.1.0
# QiLin 通道
qilin plugin --profile qilin add dsh-kylin-memory
qilin plugin --profile qilin add github:kkutysllb/dsh-kylin-memory
```

本地开发安装：`link:` 前缀（如 `dsh plugin --profile web add link:/Users/libing/kk_Projects/dsh-kylin-memory`），装完重启宿主。安装校验：`qilin plugin doctor dsh-kylin-memory` 应输出 `usable`。
