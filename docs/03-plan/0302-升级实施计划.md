# 0302 升级实施计划：记忆生命周期补全（v0.2 → v0.3）

> 状态：计划文档（2026-10-02 制定）。按 docs/02-design/0201 的缺陷编号（A1..D4/B1..B5/C*/D*）组织里程碑；每项落地后在此标记 ✅ 版本号，并同步更新 0201 对应条目、01-tech 相关文档与 release/。本文与 0301（路线图索引）保持引用关系：0301 讲做什么/为什么，本文讲怎么做/怎么验。

## 目标与非目标

**目标**：补齐记忆生命周期——事实失效（A1）、作用域隔离（D1）、检索质量底线（B1/B2/A2）、可验证性（C6/C3）。全部本地计算，不增加每轮 LLM 调用次数（维持"每轮恰好 1 次抽取"的成本红线）。

**非目标**（明确不做，防止范围蔓延）：
- 完整双时间轴/时点查询（Zep 级别）——只做轻量失效标记；
- cross-encoder reranker（B3 的重方案）——B3 只做查询拆分的轻量版；
- 向量 ANN（C2）——万级以下暴力扫描够用，推迟；
- 硬多租户（按用户物理隔离存储）——只做逻辑作用域列；
- agent 自编辑默认放开（仅作为配置项评估，见 M6）。

## M1 事实失效轻量版（A1）✅ v0.1.1（实际迁移 m17）

**设计**：失效粒度定在 **(规范化 subject, 规范化 predicate) → object** 三元组层面，零 LLM 调用：

1. 轮次记忆写入成功后（`scheduleExtract` 成功分支内），对新产生的每条 SPO，回查同 session 无关的**更早**记忆中是否存在同 `(subject, predicate)` 但 object 不同的 triple；
2. 命中则把旧 triple 标记失效（记录失效者），并给旧记忆打降权标记；
3. 召回时：若结果集中同一 `(subject, predicate)` 已有更新的记忆，被失效的旧记忆**过滤掉**（保守：只过滤有明确失效边的，不做语义推断）。

**Schema（迁移 m17，追加在 steps 末尾，不改写已有编号）**：
- `ALTER TABLE km_navigation_triples ADD COLUMN superseded_by TEXT`（NULL=有效；值为失效它的 memory id）；
- `ALTER TABLE km_turn_memories ADD COLUMN superseded_count INTEGER NOT NULL DEFAULT 0`（冗余计数，便于 km_status/RPC 展示）。

**涉及文件**：`src/store/db.ts`（m17）、`src/store/store.ts`（markTriplesSuperseded / 回查查询）、`src/index.ts`（extractOnce 成功后调用）、`src/recaller/recall.ts`（结果集过滤）、`km_stats`/RPC overview 增加失效计数。

**已知边界（写入文档）**：谓词字面匹配——"改为"/"换成"不同词不触发（保守=少误杀多漏杀）；无 SPO 的纯摘要矛盾检测不到。两者都在 0201 A1 标注为 v1 限制。

**测试**：同 (subject,predicate) 不同 object 触发失效；同 object 不触发；失效记忆从召回结果过滤；un-supersee 路径（`km_forget` 删除失效者后旧记忆恢复召回）；迁移升级路径（旧库 ALTER 生效）。

**验收**：移植上游 20 轮场景中的"事实修订"轮次做手工回归（M5 完成前用场景 JSON 的 T 序列）；`km_status` 显示失效计数；145+ 存量测试全绿。

**风险**：谓词表述差异导致漏失效（可接受，记入限制）；误失效需审计——失效关系计入 C5 的删除审计统一解决（v0.3）。

## M2 记忆作用域（D1）✅ v0.1.1（实际迁移 m19）

**设计**：逻辑作用域列，不做物理分库。

1. `km_turn_memories` / `km_messages` / `km_navigation_triples` 增加 `workspace_id TEXT NOT NULL DEFAULT 'default'`（迁移 m18，ALTER ADD COLUMN）；
2. 写入时从宿主解析 workspace：适配器经 `agents`/workspaceRegistry 防御性探测当前 agent 的 workspace id，取不到落 `'default'`；
3. 新配置 `recallScope: "all" | "same-workspace"`（默认 `all`，保持现状不破坏升级）；`same-workspace` 时召回 SQL 追加 workspace 过滤；
4. `km_forget` / RPC `memories`/`forget` 增加 workspace 过滤参数；RPC overview 增加按 workspace 分组计数。

**涉及文件**：`src/store/db.ts`、`src/store/store.ts`（写入链带 workspace + 召回过滤）、`src/index.ts`（workspace 解析 + 配置）、`cordis.patch.yml`（注释示例）。

**测试**：两 workspace 写入互不可见（same-workspace 模式）；all 模式行为与 v0.1 一致（回归）；workspace 解析失败的 'default' 回退；旧库升级后全部落 'default'。

**验收**：双 workspace 场景手工验证隔离与放行；`--dump-config` 出新配置默认值。

**风险**：workspace 解析在 DSH/QiLin 的 API 差异——防御性探测 + 'default' 兜底，最坏情况退化为现状（all）。

## M3 轮次记忆 FTS5（B1，顺带 B5 轻缓解）✅ v0.1.1（实际迁移 m18）

**设计**：

1. 迁移 m19：`CREATE VIRTUAL TABLE km_turn_memories_fts USING fts5(summary, content='km_turn_memories', content_rowid='rowid', tokenize='trigram')`——**trigram 分词器**是中文可用的关键（unicode61 不分 CJK；trigram 支持 ≥3 字符子串查询）；
2. 三个同步触发器（INSERT/UPDATE/DELETE）与旧图 `km_nodes_fts` 同款模式；
3. 召回词法路线改为：FTS5 MATCH（短语加引号）优先，FTS5 不可用或查询 <3 字符时回退现有全短语 LIKE（保留为最后兜底）；
4. B5 轻缓解：PPR 词项分数乘以记忆新鲜度衰减因子（`exp(-age_days/半衰期)`，半衰期可配 `freshnessHalfLifeDays` 默认 0=关），默认关闭不改行为，文档写明。

**涉及文件**：`src/store/db.ts`（m19）、`src/store/store.ts`（ftsSearchTurnMemories）、`src/recaller/recall.ts`（路线接入）、`src/graph/pagerank.ts` 或 rank 映射处（衰减因子）、`src/types.ts`（配置）。

**测试**：中文子串命中（"端口 9090" ↔ "9090 端口" 经 trigram 词元命中）；短查询回退 LIKE；FTS5 不可用环境降级；触发器同步（更新/删除记忆后索引一致）；衰减因子开关前后排名对比。

**验收**：词法路线在中文查询上的命中用例从"必须完整短语"放宽到"≥3 字子串"。

**风险**：trigram 索引体积（仅索引 summary，可接受）；node:sqlite 内置 SQLite 版本需 ≥3.34（22.13+ 满足，启动探测沿用旧图 FTS5 探测模式）。

## M4 实体归一化 v1（A2/B2）✅ v0.1.1（实际迁移 m20）

**设计**：**别名间接层**，不改写历史数据：

1. 迁移 m20：`km_term_aliases(term_id → canonical_term_id)` + `km_term_vectors(term_id, embedding, content_hash)`；
2. 维护期（`km_maintain`/周期维护）离线批处理：对所有导航词项的 display_text 计算 embedding，余弦 ≥ 阈值（默认 0.85，保守）的聚类为别名组，组内选最长/最具体的词项为 canonical；
3. 查询侧：种子词项查找经别名表扩展到 canonical 及其同组词项——历史 triple 不改写，检索等效合并；
4. 别名只增不自动删；RPC `memories` 通道新增 `termAliases` 只读端点供人工审计（本期不做合并工具，人工发现错合并时删除别名行即可）。

**涉及文件**：`src/store/db.ts`、`src/store/store.ts`（别名查询扩展 + 批处理）、`src/graph/maintenance.ts`（挂入维护）、`src/engine/embed.ts`（复用）、`src/rpc.ts`（只读端点）。

**测试**：同义 term 合并后跨词召回命中；阈值外不合并且无副作用；`km_forget` 删除 canonical 时别名组迁移处理；无 embedding 环境整模块跳过。

**验收**：构造 5+ 别名组的人工语料，图路线召回覆盖率对比 M4 前提升且零误合并。

**风险**：误合并污染导航（保守阈值 + 只读审计 + 可手工删行兜底）；这是算法风险最高的里程碑，若验收不达标允许降级到"仅规范化变体合并（大小写/全半角/繁简）"先落地。

## 实施顺序与依赖

```
M5（基准先行，建立回归底线）
  → M1（失效）→ M3（FTS5）→ M2（作用域）      # 一次性完成（v0.1.1 发布）
  → M6.1/6.3（CI/test 基建尽早）

```
