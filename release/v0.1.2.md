# v0.1.2

## 版本信息

- 发布日期：2026-10-03
- 基线：v0.1.1
- 主题：设计文档合规复查修复（docs/03-plan/0302 §v0.1.2 补遗）

## 新增

- `km_forget` / RPC `forget` 可选 `workspaceId` 参数：会话级遗忘按 workspace 收窄，其他 workspace 的证据与抽取水印保留；与 `memoryId` 互斥。
- RPC `overview` 新增 `turnMemoriesByWorkspace` 分组计数与 `lastProbeAt`（embedding 最近探针时间，对应 0302 M6 A5 的展示要求）；`km_status` 同步显示 lastProbeAt。
- 环境变量 `KYLIN_MEMORY_SEMANTIC_SCORE_THRESHOLD`（0..1）：语义召回余弦门槛覆盖，与显式配置共用同一 fail-closed 校验（0101 变量表早已声明，本次落地实现）。

## 变更

- 无行为性变更；`cordis.patch.yml` 仅补阈值 env 注释。

## 修复

- **事实失效误标（P1）**：`supersedeConflictingTriples` 的 subject/predicate 两个独立 IN 子查询在多 SPO 轮次发生笛卡尔积误标——从未被重述的 (subject, predicate) 也会被标记失效并从召回剔除。改为按三元组成对 EXISTS 匹配，附回归测试。
- **保留策略证据丢失（P1）**：`messageRetention.keep: referenced/recent` 的引用检查只覆盖旧图 `km_node_sources`，轮次记忆引用的事实层 Q/A 会被级联删除。补 `km_turn_memory_sources` 引用检查；引用解除后的证据仍可被后续批次回收，附回归测试。

## 删除

- 无对外删除；清理 `forgetTurnMemories` 恒真调试条件、`recall-community` 测试残留手工建表；补"空 triples 合法"合同用例。

## 兼容性

- 默认行为不变：`assistantTools: search`、`recallScope: all`、阈值 env 未设置时沿用 0.70；迁移仍为 m1–m21（无新迁移）；`messageRetention` 默认 `keep: all` 不受引用检查影响。
- Node.js ≥ 22.13.0；DSH 0.1.7+ / QiLin 3.0+ 不变。
