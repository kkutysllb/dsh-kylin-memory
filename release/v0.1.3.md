# v0.1.3

## 版本信息

- 发布日期：2026-10-04
- 基线：v0.1.2
- 主题：插件详情页设置表单（0105 UI 决策修订：四个 live 参数可视化调整）

## 新增

- **插件详情页设置表单**：web 面板 → 插件管理 → dsh-kylin-memory 详情页出现设置区，可在 UI 直接调整四个高频参数（此前只能改安装包 `cordis.patch.yml`）：
  - `freshTurnCount` 保留最近轮数（默认 5）——模型上下文保留最近多少个完整问答轮，即"多少轮之外的历史被压缩接管"的实际旋钮；
  - `maintenanceInterval` 维护节奏（默认 6）——每 N 轮执行一次图维护与消息保留 GC；
  - `recallMaxNodes` 单次召回上限（默认 6）；
  - `semanticScoreThreshold` 语义召回阈值（留空 = 默认 0.7）。
- 宿主侧 `Config` schema（`src/schema.ts`，schemastery）：四个字段全部 `.volatile()`——保存后宿主原地换值、插件不重启即生效；schema 解析保留未知键，patch 其余配置不受影响。表单保存写入 profile 用户覆盖层，bundle patch 为默认值层，支持"恢复默认"；写入按 schema 校验（阈值 -1..1、正整数约束）。
- 客户端 `src/client/`（web client bundle，`__ModuleLoader__` 契约）：keyed `plugins.bundle.config` 槽位 + `configForms` 命名空间绑定 + `whileServed` 门控（插件未加载时表单消失）；中英双语；`plugins.item` 仍不占用（官方设置页专用）。

## 变更

- volatile 字段运行时读取改为穿透引用：`readLive()`（types.ts）解包宿主 live 引用；`KmConfig` 的 `compactTurnCount` / `freshTurnCount` / `recallMaxNodes` / `semanticScoreThreshold` 类型变为 `LiveValue<number>`，压缩窗口、维护节奏、召回上限与阈值在设置页保存后立即生效。
- `KYLIN_MEMORY_SEMANTIC_SCORE_THRESHOLD` 环境变量语义不变：仅在配置与用户覆盖均未设置时生效。
- 构建产出 `lib/client.js`（settings 表单）；schemastery 3.18.4 + cosmokit 1.8.5（MIT，宿主同版本）vendor 至 `third_party/` 并入 host bundle——宿主不向插件提供 `@deepseek-ai/*` 模块的部署约束保持成立。
- smoke 第 4 节由"无 client 块"反转为正向契约检查（ModuleLoader 包装、keyed 槽位、configForms 绑定、UI 原语经 shell require）。

## 兼容性

- 默认行为不变：四个字段默认值与 v0.1.2 一致；`maintenanceInterval` 映射 `compactTurnCount` 的语义不变；不占用新迁移（仍 m1–m21）。
- 设置表单仅在宿主提供 settings/configForms 服务的 web profile 出现；极简 profile 插件功能完整（RPC 通道同为动态可选面）。
- `PluginConfig` 类型导出更名（原 `Config` 接口让位给宿主读取的 schema `Config` 导出）。
